# Gravitask

마감이 다가오는 걸 읽지 않고 **느끼게** 하는 바탕화면 할 일 위젯.
Windows와 macOS에서 돕니다.

할 일은 마감을 향해 떨어집니다. 이름은 거기서 왔습니다.

기존 할 일 위젯은 두 극단으로 갈라져 있습니다. Rainmeter 계열은 예쁘지만 할 일
관리가 안 되고, Microsoft To Do 계열은 기능은 완전하지만 "3일 남음"을 글자로
알려줄 뿐 시각적 압력이 없습니다. 이 프로젝트는 그 사이를 노립니다.

## 핵심 아이디어 — 3구역 시간축

모든 주제가 시간축 하나를 공유하고, 주제마다 레인을 하나씩 가집니다.

```
        학업            생활
      ┌──────────────┬──────────────┐
      │ [학회 26일]  │              │   대기 — 하루 이상 남은 일.
      │ [논문  9일]  │ [월세 17일]  │        레인별 균등 간격, 순서만 전달
  24H ├ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─┤   ← 이 선을 넘는 순간이 곧 알림
  12h │              │ [건강검진]   │   활주로 — 24시간 이내.
  DUE ┝━━━━━━━━━━━━━━━━━━━━━━━━━━━━┥        실제 시간 눈금 위에 놓임
      │ [확률론]     │              │   지남 — 오래 밀릴수록 깊이 가라앉음
      └──────────────┴──────────────┘
```

**뼈대는 한 번만 그립니다.** 주제마다 축을 통째로 복제하면 공간이 주제 수에
비례해 늘고, 축이 다르면 높이의 의미도 달라져 "학업의 3시간 뒤"와 "생활의
1시간 뒤" 중 뭐가 급한지 비교할 수 없습니다. 리마인더가 답해야 할 가장 중요한
질문을 구조가 막는 셈입니다.

**구역마다 표현이 다릅니다.** 한 축에 6시간과 26일을 같은 방식으로 그리면
가시성이 무너집니다. 먼 일정은 순서만 알면 되고, 임박한 일정은 정밀한 시간이
필요합니다.

**쓸 일이 없는 구역은 자리를 비웁니다.** 오늘 마감이 없으면 활주로가 접히고,
밀린 일이 없으면 지남 구역이 사라집니다. 붐비면 반대로 늘어나고, 창이 그
크기를 따라갑니다. 위젯에서 스크롤은 전체를 한눈에 본다는 전제를 깨므로 최후의
수단입니다.

## 임박 효과

색만으로 급함을 표현하면 색각 이상 사용자에게 전달되지 않습니다. 남은 시간을
**0~1 긴급도 값 하나**로 계산하고 여러 채널이 함께 반응합니다.

| 채널 | 여유 | 긴급 |
| --- | --- | --- |
| 위치 | 대기 구역 위쪽 | 활주로 바닥, 마감선에 근접 |
| 색 | 저채도 청록 | 고채도 적색 |
| 형태 | 둥근 모서리 | 모서리 축소, 좌측 스트라이프 굵어짐 |
| 타이포 | 상대 표기 "9일 남음" | 절대 시각 "23:59까지" |
| 모션 | 정지 | 6초 주기 호흡 |

야간에는 채도와 모션이 자동으로 억제됩니다. 밤에 빨간 게 깜빡이면 위젯을 끄게
되니까요.

**주제에는 색을 쓰지 않습니다.** 카드가 이미 긴급도 색을 쓰고 있어서 주제까지
색을 가지면 "이 색이 급하다는 뜻인지 주제라는 뜻인지" 헷갈립니다. 주제는 레인
위치와 이름으로 구분됩니다.

## 쓰는 법

**할 일 추가** — 한 줄로 적습니다. `확률론 과제 내일 오후 6시`처럼 쓰면 제목과
마감을 알아서 나눕니다. 파싱 결과는 입력줄 아래 `마감` 칩에 드러나고, 직접
고치면 그쪽이 우선합니다. 파싱은 편의일 뿐 최종 결정권은 사용자에게 있습니다.

**전역 단축키** — `Ctrl` + `Alt` + `G`. 어디서든 위젯을 띄우고 입력칸에 커서를
둡니다.

**주제 편집** — 위젯 상단의 `주제 편집`. 이름 변경·순서 이동·추가·삭제. 할 일이
남은 주제는 지울 수 없습니다. 되돌릴 방법이 없는 삭제는 막습니다.

**트레이 메뉴** — 위젯은 항상 다른 창 뒤에 깔리고 작업표시줄(macOS는 Dock)에도
뜨지 않으므로, 트레이가 되찾는 수단입니다. macOS에서는 메뉴 막대 오른쪽입니다.
`위젯 보이기` / `숨기기` / `맨 앞에 고정` / `로그인 시 자동 시작` / `종료`.

**창 위치는 기억됩니다.** 크기는 내용에 맞춰 매번 계산합니다.

## 개발

```bash
npm install
npm run tauri dev  # 실제 위젯 (Rust 툴체인 필요)
npm run dev        # 브라우저에서 UI만 (http://localhost:5273)
npm run check      # 타입 검사
npm run test:parse # 자연어 파서 명세
```

`npm run dev`는 가짜 바탕화면 위에 위젯을 띄웁니다. UI 작업은 재빌드가 없어
이쪽이 훨씬 빠릅니다.

## 구조

| 파일 | 역할 |
| --- | --- |
| `src/lib/theme.json` | 색·치수·모션·글자 크기를 한 곳에 모은 테마 |
| `src/lib/urgency.ts` | 긴급도 단일 진실 공급원. 모든 시각 속성이 여기서 파생 |
| `src/lib/layout.ts` | 3구역 배치 계산. 구역 높이, 레인, 겹침 밀어내기 |
| `src/lib/parseInput.ts` | 한국어 자연어 입력 파서 |
| `src/lib/types.ts` | `Task`와 `TaskSource` 경계 |
| `src/lib/components/Column.svelte` | 시간축과 레인 렌더러 |
| `src/lib/components/QuickAdd.svelte` | 입력, 주제 고르기, 마감 날짜·시각 |
| `src-tauri/src/desktop/` | 위젯을 바탕화면 바로 위에 세워 두는 처리. 플랫폼마다 방법이 정반대라 파일이 갈립니다 |

`theme.json`은 사람이 읽고 고칠 수 있게 열어둔 파일입니다. 색 램프, 카드 반경,
글자 크기, 모션 강도, 레인 폭, 24시간 경계 시간을 바꿔 테마를 만들 수 있습니다.

### 투명도 조절

배경화면이 어두운 편이라 더 투명해도 괜찮다면 `surface.background` 알파값을
낮추세요.

```json
"surface": { "background": "rgba(18,19,27,0.72)" }
```

기본값 `0.72`는 **순백 배경화면 위에서도** 본문 대비 6.65:1, 보조 텍스트
4.62:1을 확보하도록 잡은 값입니다(WCAG AA 기준 4.5:1). 낮출수록 배경이 비쳐
보이지만 밝은 배경화면에서 글자가 묻히기 시작합니다. `0.55` 아래로는 권하지
않습니다.

투명 창에서는 CSS `backdrop-filter`가 아무것도 흐리지 못합니다 — 창 뒤
바탕화면은 페이지 바깥이라 흐릴 대상이 아닙니다. 글자 대비는 전적으로 이
스크림이 책임집니다. Windows acrylic도 써봤지만 뺐습니다. Windows 11은 비활성
창의 아크릴을 단색으로 대체하는데, 이 위젯은 거의 항상 비활성이라 회색 폴백만
보게 됩니다.

### 레인 폭

주제가 늘면 레인이 좁아집니다. `maxWidth`(내용 폭 상한)와 `laneMin`(레인 하한)
사이에서 나눠 쓰므로, 주제가 4개를 넘어도 위젯이 계속 넓어지지는 않습니다.
좁아져 잘린 제목은 카드에 마우스를 올리면 펼쳐집니다.

## 배포

태그를 밀면 GitHub Actions가 Windows 인스톨러(`.exe`)와 macOS 디스크
이미지(`.dmg`)를 만들어 Releases에 **초안**으로 올립니다. 내용을 확인하고 직접
게시하는 흐름입니다.

macOS 쪽은 `universal-apple-darwin`으로 한 번에 냅니다. Intel과 Apple Silicon을
따로 내면 받는 사람이 자기 Mac이 어느 쪽인지 알아야 하고, 잘못 받으면 실행이
안 되는 이유를 설명해야 합니다. 용량 몇십 MB와 바꿀 만한 일이 아닙니다.

두 잡은 나란히가 아니라 **차례로** 돕니다. 둘 다 같은 릴리스의 `latest.json`을
고쳐 쓰는데, 동시에 쓰면 늦게 끝난 쪽이 먼저 끝난 쪽의 항목을 지울 수
있습니다. 그러면 한쪽 플랫폼 사용자 전원이 업데이트 경로를 잃습니다.
**초안을 게시하기 전에 `latest.json`에 두 플랫폼이 다 들어 있는지 확인하세요.**

```bash
npm version patch       # 커밋과 태그를 함께 만듭니다
git push --follow-tags  # 커밋만 밀면 워크플로가 돌지 않습니다
```

`tauri.conf.json`은 버전을 `../package.json`에서 읽으므로 따로 맞출 것이
없습니다. 두 곳에 같은 숫자를 적어 두면 언젠가 한쪽만 고치게 됩니다.

업데이터는 릴리스에 함께 올라가는 `latest.json`을 봅니다. 서명 개인 키는
저장소에 두지 않고 GitHub Actions Secrets에만 있습니다.

| 시크릿 | 내용 |
| --- | --- |
| `TAURI_SIGNING_PRIVATE_KEY` | `gravitask.key` 파일 내용 전체 |
| `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` | 키 생성 시 정한 비밀번호 |

**개인 키를 잃으면 업데이트 경로도 잃습니다.** 기존 사용자는 다른 키로 서명된
업데이트를 거부하므로 전원이 수동 재설치를 해야 합니다. 백업해 두세요.

릴리스 워크플로는 태그 푸시에서만 돕니다. 이 저장소는 공개라, `pull_request`로
트리거하면 포크에서 온 코드가 서명 키에 접근할 수 있습니다.

## 알려진 제약

- **바탕화면 유지 동작은 환경에 따라 다를 수 있습니다.** Windows에서는 포커스가
  없을 때 '바탕화면 바로 위'로 자리를 되돌려 `Win`+`D`를 견디는데, 이 동작은
  Windows 11 한 대에서만 검증했습니다. 다른 셸 확장(Fences, 배경화면 엔진 등)과
  z-order를 두고 다툴 수 있습니다.
- **macOS 쪽은 아직 아무것도 실제 기기에서 확인하지 못했습니다.** 개발 환경이
  Windows뿐이라 CI 컴파일까지가 여기서 할 수 있는 전부입니다. 특히 '데스크탑
  보기'를 견디는지(`stationary`), 서명 없는 앱에서 알림이 뜨는지, 업데이터가
  `.app` 교체를 해내는지는 받아 본 사람만 알 수 있습니다.
- **서명 인증서가 없어** Windows는 첫 실행에서 SmartScreen 경고가, macOS는
  "손상되었기 때문에 열 수 없습니다"가 뜹니다. 릴리스 노트에 우회 방법을
  적어 둡니다.
- **잘못 만든 항목을 지울 방법이 없습니다.** 완료 체크는 "했다"는 뜻이라 오타로
  만든 항목에는 맞지 않습니다.
- **활주로가 붐비면 시간 위치가 어긋납니다.** 카드가 겹치지 않도록 밀어내는데,
  그만큼 "같은 높이 = 같은 시간"이 깨집니다. 정확한 값은 카드의 "N시간 남음"이
  알려줍니다.

## 로드맵

- **v1** — 로컬 할 일만. 캘린더 연동 없음. 서명 없이 배포
- **v1.1** — 비공개 iCal(ICS) 주소로 캘린더 추가. `TaskSource` 구현체를 하나 더
  끼우는 형태라 UI 변경 없음. 항목 삭제(우클릭 메뉴)도 함께
- **v1.2** — 코드 서명 인증서

캘린더는 OAuth 대신 ICS로 갑니다. Google Calendar 스코프는 민감 스코프로 분류돼
검증 전까지 평생 100명 상한이 걸리는 반면, 비공개 iCal 주소는 심사가 없고
Apple·Outlook 캘린더까지 같은 코드로 지원됩니다.

일정은 '구간'이고 할 일은 '점'이라 성질이 다릅니다. 캘린더를 붙일 때 `Task`에
끝 시각을 억지로 얹지 말고 별도 타입으로 나누는 편이 낫습니다.

## 기술 스택

Tauri 2 + Svelte 5 + TypeScript. Tauri는 OS가 이미 갖고 있는 웹뷰를 씁니다 —
Windows는 WebView2(Chromium), macOS는 WKWebView(WebKit). 그래서 배포 용량과
메모리가 Electron보다 크게 작고, 하루 종일 켜두는 위젯에서는 이 차이가
결정적입니다.

대신 렌더러가 플랫폼마다 다르다는 값을 치릅니다. 다만 이 위젯은 배치를
`getBoundingClientRect` 실측으로 계산하므로, 글꼴 메트릭이 달라져도 카드가
겹치거나 창 크기가 어긋나지 않습니다 — 3구역 시간축은 두 웹뷰에서 같은
코드로 섭니다.

`Win`+`D`를 견디는 방법으로 WorkerW 부착(창을 바탕화면의 자식으로 만드는 고전
기법)도 시도했지만 걷어냈습니다. 붙은 창은 포커스 활성화 체인 밖이라 WebView2가
마우스를 전혀 받지 못해 클릭·드래그·스크롤이 모두 죽습니다. Rainmeter가 같은
기법으로도 조작을 유지하는 건 순수 Win32 창이라 자식 창에서도 마우스 메시지를
직접 처리하기 때문이고, 웹뷰에는 그 경로가 없습니다. 지금은 z-order만 관리해
같은 목적을 달성합니다.
